# Антиспам для Telegram

Готовый к настройке бот на Python 3.11+ без сторонних библиотек. Его главная задача — замечать аккаунты-боты в группе комментариев, показывать их список и удалять автоматически или вручную. Дополнительно он фильтрует спам-сообщения. Платные сервисы и ИИ не нужны. Пока процесс запущен и есть интернет, бот работает.

## Что он умеет

- Сохранять список ботов, замеченных при вступлении или активности: `/bots`.
- Автоматически удалять и блокировать новых ботов: `/botguard ban`.
- Сохранять обычные аккаунты, пойманные на спаме, в тот же список и блокировать их в режиме `/mode ban`.
- Удалять одного бота: `/botban ID`; снять ошибочную блокировку: `/botunban ID`.
- Предварительно показать число целей и массово удалить уже обнаруженных ботов: `/botclean`, затем `/botclean confirm` (до 50 за запуск).
- Не удалять самого себя, ботов-администраторов и ID из белого списка `/trust add ID`.
- Запрещать ссылки, включая скрытые ссылки и ссылки в подписях к фото.
- Удалять сообщения со стоп-фразами, которые задаёт администратор.
- Обнаруживать флуд (шестое сообщение за 15 секунд) и одинаковый текст (третий повтор за 15 секунд).
- Сначала наблюдать, затем по вашей команде удалять; есть пауза.
- Показывать статистику за 24 часа и 7 дней, последние 10 срабатываний и ошибки удаления.
- Пропускать администраторов и пользователей белого списка в группах, а также автоматические публикации из привязанного канала.
- Удалять вручную по команде `/del` ответом на сообщение.

Удаление аккаунтов-ботов работает в группе и в привязанной группе комментариев. Посты в самом канале проверяются на ссылки и стоп-фразы: там автором обычно выступает канал, поэтому белый список пользователей и проверка флуда не применяются. Анонимные администраторы группы освобождены от фильтрации, но управлять ботом должны от своего аккаунта. Сообщения от сторонних каналов в группе проверяются.

## Запуск за несколько шагов

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте название и username. Скопируйте полученный токен. Не публикуйте его и не отправляйте в переписку.
2. В терминале выполните:

   ```bash
   cd /home/hromovpi/Workspace/telegram-antispam
   cp .env.example .env
   ```

3. Откройте `.env` в редакторе и замените `BOT_TOKEN`. Для получения своего ID можно временно оставить `OWNER_IDS` пустым. Запустите `python3 bot.py`, откройте своего бота в Telegram и отправьте `/start`: бот покажет ваш ID. Остановите процесс Ctrl+C, впишите ID в `OWNER_IDS` и запустите снова. Несколько владельцев перечисляются через запятую.
4. Добавьте бота в нужную группу администратором с правами **блокировки участников** и удаления сообщений. Для комментариев нужна именно группа обсуждения, привязанная к каналу. Найдите её в настройках канала → «Обсуждение». Право назначения администраторов не нужно.
5. От своего аккаунта владельца отправьте в группе `/setup`, затем `/check`. Этот аккаунт должен быть администратором группы.
6. Включите основную защиту от ботов:

   ```text
   /botguard ban
   /bots
   ```

   С этого момента новый замеченный аккаунт с признаком `is_bot` будет удалён и заблокирован. Чтобы сначала только собирать список, используйте `/botguard observe`. Отключение: `/botguard off`.

7. При необходимости настройте фильтр сообщений:

   ```text
   /phrase add заработок без вложений
   /phrase add гарантированный доход
   /links on
   /settings
   ```

   `/links on` запрещает все распознанные ссылки обычных участников, в том числе полезные. Если ссылки нужны, оставьте `/links off`. Стоп-фразы работают как подстроки: выбирайте достаточно конкретные выражения.

8. Проверьте поведение с аккаунта обычного участника. Посмотрите `/bots`, `/recent` и `/stats`. Затем включите `/mode ban`, чтобы при совпадении с правилами удалялись и сообщение, и отправитель. Более мягкий `/mode delete` удаляет только сообщение; `/mode observe` лишь записывает срабатывание; `/mode off` приостанавливает фильтр сообщений. Настройка `/mode` не выключает отдельную защиту `/botguard`.

Изначально защита от ботов и фильтр сообщений включены в режиме наблюдения, запрет ссылок выключен, список стоп-фраз пуст. Флуд и повторы отслеживаются сразу. Заблокированного бота можно вернуть командой `/botunban ID`, но Telegram не добавит его обратно автоматически.

## Очистка уже обнаруженных ботов

```text
/bots
/botclean
/botclean confirm
```

Первая команда выводит до 100 последних официальных bot-аккаунтов и обычных аккаунтов, пойманных фильтром на спаме, с ID и состоянием. Вторая показывает число кандидатов. Третья блокирует до 50 кандидатов за один запуск и сообщает результат; повторите её, если остались необработанные записи. Администраторы не удаляются: сначала вручную снимите с них права. Полезного бота или ошибочно отмеченного пользователя заранее добавьте в исключения командой `/trust add ID`.

## Срочная проверка вступивших сегодня

Обычный Bot API не умеет запрашивать список подписчиков задним числом. Для этой задачи в проекте есть `scan_members.py`: он через официальный MTProto API запрашивает доступных недавних участников и их даты вступления, оставляет вступивших с указанной даты, формирует CSV и только после ручного подтверждения блокирует выбранные ID. Авторизация выполняется тем же bot-аккаунтом — вводить номер телефона и код от личного Telegram не нужно.

1. Получите `api_id` и `api_hash` в разделе **API development tools** на [my.telegram.org](https://my.telegram.org). Не публикуйте `api_hash`: Telegram не позволяет его перевыпустить.
2. Добавьте значения в `.env`:

   ```dotenv
   TELEGRAM_API_ID=12345678
   TELEGRAM_API_HASH=ваш_api_hash
   TIMEZONE=Europe/Saratov
   ```

3. Убедитесь, что бот назначен администратором именно канала и имеет право блокировать подписчиков. Установите отдельную зависимость сканера:

   ```bash
   cd /home/hromovpi/Workspace/telegram-antispam
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements-scan.txt
   ```

4. Запустите проверку. Для публичного канала удобнее username:

   ```bash
   .venv/bin/python scan_members.py --chat @имя_канала --since today
   ```

   Для приватного канала используйте числовой ID вида `-1001234567890`. Скрипт учитывает `TIMEZONE`, поэтому `today` начинается с 00:00 по указанному часовому поясу.

   Если обычный запуск вернул ровно 200 строк, это предел выборки недавних участников Telegram. Для полной сегодняшней волны используйте журнал администратора:

   ```bash
   .venv/bin/python scan_members.py --chat -1001234567890 --since today --full-log
   ```

   Telegram разрешает читать административный журнал только пользовательскому аккаунту. При первом запуске Telethon запросит в терминале номер телефона, код из Telegram и, если включена, двухэтапную аутентификацию. Войдите аккаунтом, который является администратором канала. Код и пароль не сохраняются проектом; локальная авторизованная сессия хранится в игнорируемом Git файле `data/mtproto_admin.session`. Последующие запуски повторного входа не требуют.

   Если вы не хотите входить личным аккаунтом, можно запустить расширенный поисковый обход от имени бота:

   ```bash
   .venv/bin/python scan_members.py --chat -1001234567890 --since today --search-sweep
   ```

   Он выполняет до 500 запросов по латинским, цифровым, кириллическим и украинским префиксам, объединяет результаты по ID и рекурсивно уточняет запросы, которые снова упёрлись в 200. Во время работы показываются progress bar, число запросов, текущий префикс и количество найденных уникальных аккаунтов. Telegram не гарантирует полноту поиска: аккаунты с некоторыми необычными именами могут не попасть в результат. Число запросов можно изменить через `--max-search-queries`, допустимый диапазон — от 1 до 4000. Для отключения динамического вывода используйте `--no-progress`.

   В приглашении введите номер телефона вида `+79991234567`, а не `BOT_TOKEN`. Если по ошибке вошли токеном бота, безопасно переместите ошибочную сессию в резервную копию и повторите вход:

   ```bash
   .venv/bin/python scan_members.py --chat -1001234567890 --since today \
     --full-log --reset-user-session
   ```

5. В каталоге `reports/` появятся два файла:

   - `joins-....csv` — все найденные вступления, время, профильные признаки, плотность вступлений, оценка риска и причины;
   - `approved-ids-....txt` — кандидаты, но все ID закомментированы символом `#` и пока не могут быть удалены.

6. Откройте CSV и проверьте кандидатов. В `approved-ids-....txt` удалите первый `#` только у тех ID, которые действительно нужно заблокировать. Затем выполните:

   ```bash
   .venv/bin/python scan_members.py --chat @имя_канала --since today \
     --apply reports/approved-ids-ГГГГММДД-ЧЧММСС.txt --confirm-ban
   ```

   Если файл был создан полным режимом, при применении обязательно повторите `--full-log`, иначе свежая проверка снова увидит только 200 участников и отклонит остальные ID:

   ```bash
   .venv/bin/python scan_members.py --chat -1001234567890 --since today --full-log \
     --apply reports/approved-ids-ГГГГММДД-ЧЧММСС.txt --confirm-ban
   ```

Без одновременно заданных `--apply` и `--confirm-ban` сканер никого не блокирует. Он также отклоняет ID, которых нет в свежем отчёте, исключает администраторов из кандидатов и пишет результат каждой блокировки в `reports/ban-audit-....json`.

Оценка риска не доказывает, что обычный аккаунт является ботом. Точно определяется только официальный признак Telegram `bot`. Для пользовательских аккаунтов учитываются удалённый профиль, отсутствие имени, username или фото и количество вступлений за одну минуту. Поэтому CSV нужно проверить вручную. Файлы `reports/`, `.env` и MTProto-сессия в `data/` исключены из Git: в них есть закрытые данные.

## Управление каналом из личной переписки

Добавьте бота администратором канала с правом удаления сообщений. Владелец бота, который также администратор канала, пишет ему в личку:

```text
/setup -1001234567890
/phrase -1001234567890 add нежелательная фраза
/mode -1001234567890 delete
/stats -1001234567890
```

Замените пример реальным числовым ID. У публичного канала его можно получить через `getChat` Bot API по `@username`; также ID часто доступен в панели уже подключённого сервиса управления каналом. У приватного канала ссылку на пост вида `t.me/c/1234567890/42` можно преобразовать в ID `-1001234567890`. Для группы команды проще отправлять непосредственно в ней: ID не нужен.

Все команды перечислены в `/help` в личной переписке. В группе настройки могут менять только текущие администраторы. Самое первое подключение дополнительно требует ID из `OWNER_IDS`. Белый список: `/trust add 123456789`, удаление из списка: `/trust remove 123456789`. Удаление фразы: `/phrase remove нежелательная фраза`.

## Постоянная работа

На компьютере: `python3 bot.py`. Если закрыть процесс или выключить компьютер, защита остановится. Для круглосуточной работы используйте постоянно включённый сервер. При наличии Docker:

```bash
docker compose up -d --build
docker compose logs --tail=50 -f
```

SQLite сохраняется в Docker volume `bot-data`; при обычном запуске — в `data/bot.sqlite3`. Делайте резервную копию базы при остановленном боте. Запускайте только один экземпляр на токен. Бот использует long polling, входящие порты и домен не требуются. Ранее установленный webhook нужно отключить через `deleteWebhook` Bot API; бот не снимает чужой webhook автоматически.

## Ограничения и данные

- Telegram Bot API не отдаёт боту полный список подписчиков канала или участников группы. Поэтому `/bots` показывает ботов, которых программа увидела после запуска: при вступлении, изменении членства или доступной активности. Уже находящийся в группе молчащий бот может не попасть в список. В самом канале очистить старый список подписчиков через обычный Bot API нельзя.
- Обычный режим `scan_members.py` получает доступную выборку недавних участников через MTProto; Telegram ограничивает её примерно 200 записями. Режим `--full-log` читает полный доступный административный журнал через личный аккаунт администратора. Глубина журнала также ограничена Telegram, поэтому запускайте проверку как можно скорее после накрутки.
- Автоматическое удаление основано на официальном поле Telegram `is_bot`. Оно находит аккаунты, зарегистрированные как боты, но не распознаёт обычные пользовательские аккаунты, которыми управляет программа или ферма.
- Telegram обычно разрешает удаление сообщений младше 48 часов. Очередь необработанных обновлений хранится Telegram не более 24 часов. [Документация Bot API](https://core.telegram.org/bots/api).
- Это фильтр по правилам, а не универсальный распознаватель рекламы. Спам на картинках, в аудио и сложные обходы текста он не распознаёт. Упоминания `@username` сами по себе не запрещены. Совпадения возможны и у обычных сообщений.
- Флуд считается по времени обработки ботом; после долгого простоя очередь может дать ложные срабатывания. На время проверки после простоя используйте наблюдение.
- База хранит настройки, ID проверенных сообщений и отправителей, хеш нормализованного текста, время и причины срабатывания. Исходные тексты сообщений не сохраняются. История автоматически очищается через 30 дней; настройки остаются. Ограничьте доступ к базе и `.env`.
- Статистика считает только проверенные сообщения; исключённые администраторы, доверенные пользователи и сообщения при паузе не учитываются. Правки учитываются в количестве сообщений один раз, но могут создавать несколько событий. При сбое между действием Telegram и записью результата повторная обработка возможна.
- Ошибки удаления видны в `/stats`, `/recent` и журнале. Бот не выдаёт неудачное удаление за успешное. Проверка прав участника делается через Telegram; при сетевой ошибке обработка повторяется. Для очень больших чатов понадобится оптимизация запросов и очереди.

Можно развить проект: добавить проверку обычных аккаунтов-новичков кнопкой, разрешённые домены и ежедневный отчёт в личку. Эти возможности пока не реализованы.

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

Тесты работают без токена и сети. Проверяют обнаружение и блокировку ботов, исключения, права, фильтры, редактирование, режим наблюдения, ошибки удаления и статистику. Для полноценной проверки в Telegram нужны ваш токен и тестовая группа.
